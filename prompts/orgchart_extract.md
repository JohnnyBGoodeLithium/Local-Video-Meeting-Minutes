# Org Chart 提取 Prompt（可复用）

用途：把组织架构图（PDF 转出的页图 / 流程图截图）交给视觉语言模型（VLM），
提取结构化的人员与汇报关系，生成可编辑的 org chart 草稿。

适用：任何支持图片输入的 VLM（本项目用本地 MiMo-VL-Miloco-7B；其他团队可换
Qwen-VL / GPT-4o 等，prompt 不变）。**涉及人名与架构，请注意数据合规——
本项目约束为全本地处理，云端模型需单独授权。**

## 输入准备

- PDF 先转页图：`pdftoppm -png -r 110 input.pdf page`（110 DPI 足够，太高浪费 token）
- 逐页调用，每页一次请求；不要把多页拼成一张大图（字会糊）

## 页面提取 Prompt（正文，逐页发送）

```text
这是一页组织架构图（或人员名单）。请提取页面上出现的所有人员，每行一条，格式：
姓名 | 职务 | 上级姓名

规则：
- 上级根据连线或缩进层级判断；判断不出上级就留空（行末的 | 保留）
- 只输出上述格式的行，不要标题、不要解释、不要 markdown
- 不要输出思考过程，不要输出 `<think>`、`</think>` 或任何分析说明
- 看不清的名字不要猜，跳过该行
- 没有人员的页面输出空
- 姓名以页面上的原始完整写法为准；不要翻译中文名，不要生成拼音，
  不要把英文名补成完整姓名，不要缩写、拆分或合并不同写法；
  中文名、全拼、英文名加姓氏可能属于同一个人，也可能是不同人，照原文分别输出；
  同一个人可能在本文件的其他页面重复出现，照常输出即可，合并由后处理完成
```

## 后处理规范（重要，直接决定可用性）

跨页重复是常态（总览页与团队页会重复出现同一个人），按下述规则合并：

1. **规范化**：名字去首尾空格、大小写归一、连续空白合一，作为主键去重；
   后出现的页只补缺（title/leader 为空才补）。
2. **变体不自动合并**：中文名、全拼、英文名、英文名+姓氏或单词条名即使相似，
   也只进入“疑似同一人”候选；只有人工确认后才挂到同一稳定人员 ID。
3. **leader 待确认**：被引用但不存在的上级保留为 unresolved 关系，不自动创建人员；
   图形编辑器中由用户选择已有上级、新建人员或清空关系。
4. **自指清理**：leader == 自己的名字时清空 leader。
5. **冲突保留**：同一人出现两个不同上级时，保留先见者，把冲突写进 note
   （如 `leader冲突:A|B`），由人工在编辑器里裁决——不要自动猜。

## 本项目中的用法

```bash
# 1. 在 Web 后台(/admin)上传 PDF(自动渲页图)，或用 pdftoppm 手动转
# 2. 提取（读取本文件的 prompt；输出 speaker_bank/orgchart_draft.json）
.venv/bin/python bin/orgchart_extract.py <参考文件名>
# 3. /admin 点"载入提取草稿" → 树状编辑器检查修改 → 保存为 orgchart.json
# 4. 生成层级图(VS Code Mermaid 扩展预览)
.venv/bin/python bin/orgchart_mermaid.py
```

其他团队复用：取上面的 prompt 正文 + 后处理规范，套到任意 VLM 的
"逐页图片问答"循环即可；输出统一为 `姓名 | 职务 | 上级姓名` 行格式，
后处理逻辑照抄第 2 节，尤其不得根据拼写相似度自动合并身份。
