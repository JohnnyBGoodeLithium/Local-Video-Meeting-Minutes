# 本地视觉处理与恢复

## 路径与证据

会议页、网络/本地视频镜头、现场照片使用 `visual-result/v1`。先独立读图，再把结构化观察与对应语音按对象、指标、时期、单位、预测/实际对照。模型不得把展示方案当作会议批准，也不得用语音猜填模糊图片。

固定字段包括类型、标题、状态、摘要、文字区域、读数、表格、图表、解释与未解决项。表格行宽必须一致；未知单元格是 null。数值同时保存原文、数值、单位、时期与限定词；百分比 14% 的 value 为 14、unit 为 %。图表估读值与印刷值分开。所有区域使用原图归一化坐标。前端从已校验字段生成固定 HTML，不执行模型 HTML。

`page_desc.json` 保留初读 records 与独立 reviews；兼容 desc 是投影。缓存绑定图像内容、模型标识/本地文件指纹、管理员 revision、schema 与提示词。替换远端别名背后的本地模型时必须同时更新 `MEETING_VL_REVISION`。旧 Markdown 可阅读，但不能作为新的完整结构化缓存。初读和复核冲突、复核遗漏或仍有未读项均不标为解决。

## 本地部署

默认不增加 OCR 或小模型串行关卡。共享实例需推理服务真正加载匹配视觉投影器并通过图像请求验证，单纯 `/models` 中有别名不证明视觉能力。以下变量只配置 loopback 端点：

```sh
MEETING_VL_API=http://127.0.0.1:11435/v1
MEETING_VL_MODEL_ID=your-shared-vision-alias
MEETING_VL_MODEL=/path/to/local/model.gguf
MEETING_VL_MMPROJ=/path/to/matching/mmproj.gguf
MEETING_VL_REVISION=your-model-and-projector-revision
MEETING_VL_STRUCTURED_MAX_TOKENS=3072
MEETING_VL_PAGE_TIMEOUT=120
```

推理服务的同一模型配置必须包含 model 和 mmproj；应用不会给外部服务热加投影器。文本与视觉都调用同一实例才节约第二份权重；权重驻留、KV 前缀缓存与已读取的证据结果缓存是不同层。独立图片请求不把上一张模型答案作为事实输入。

按需复核使用 `MEETING_VL_REVIEW_MODEL`、`MEETING_VL_REVIEW_MMPROJ`；仅未读项、关键来源分歧或明确请求触发，优先裁剪疑难区域。默认每轮最多 12 页/120 秒，耗尽后保留待核。模型参数更多不自动意味着更准确，启用前用代表性困难图表比较。

## 预算与场景

| 场景 | 采集与处理 |
|---|---|
| 会议 | 保留页面时间关系，必要时读取原生帧；按会议讨论语义汇总 |
| 视频 | 默认截图上限为 0（不截断），每轮初读最多 80 页，逐页文字分析有独立预算；未处理页明确保留 |
| Live | 周期截图保留，独立视觉线程单次请求默认 12 秒，语音积压时让路；优先书签和近期帧，旧积压延后 |

`MEETING_VL_MEDIA_MAX_NEW_PAGES=0` 可使一次离线重跑读取全部保留页，代价是更长完成时间。自动初读失败只做一次有界紧凑重试；截断或非法 JSON 不缓存为成功。ASR/VL 对照默认每轮 12 页，无法完成的保持 pending，不伪造一致。Live 结束后复用录像和 ASR，转入离线完整流程；临时短读不能冒充完整视觉复核。

## 升级与重跑

先备份旧派生结果及其 revision，保留源音视频、ASR、人工身份和用户修改。对旧 capped 视频重新抽帧；时间轴/图像改变时归档旧描述和原生帧缓存，避免新页号使用旧读数。随后执行视觉补充与下游纪要生成，核对未读页、来源分歧、截图数量和处理耗时。耗时长时旧结果仍可供阅读；不要通过删除母版或重跑 ASR 解决视觉失败。

完成初读仅表示模型按合同返回了观察，不表示所有细节客观正确。复杂图表看不清时明确保留疑点，不承诺恢复不存在的像素信息。
