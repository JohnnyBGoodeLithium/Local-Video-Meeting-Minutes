# 产品说明

本文回答产品长期解决什么问题、服务谁、稳定能力和非目标。适合产品、管理和技术评审；当前周状态看 [STATUS.md](STATUS.md)，实现边界看 [ARCHITECTURE.md](ARCHITECTURE.md)，叶功能看 [PRODUCT_FUNCTIONS.md](PRODUCT_FUNCTIONS.md)。

## 一句话定义

Local Video Meeting Minutes 是一个本地优先的会议上下文编译器：把会议和高信息密度视频整理为身份明确、证据可回跳、允许人工校正并能被不同消费方继续使用的上下文。

它不是靠某一个模型成立的纪要应用。长期价值放在人员身份、原声和画面的证据关系、可逆修正，以及同一份事实向 Viewer、通用 AI 工具和知识库的可移植投影。

## 用户与核心任务

| 用户 | 核心任务 | 产品提供 |
|---|---|---|
| 会议参与者或缺席者 | 少回听，快速理解结构并核对关键原话 | 脉络、纪要、时间回跳、人物核听 |
| 会议准备者 | 修正转写和身份，形成可信交付物 | 逐字稿修正、人物确认、证据、可撤销写入 |
| 视频研究者 | 定位高信息密度片段并保留第一手来源 | 论证脉络、关键画面、原视频链接 |
| 知识维护者 | 把一手内容交给通用模型或知识库 | AI Context、KB projection、revision 回执 |
| 技术评审者 | 理解数据边界、模型可替换性和失败恢复 | canonical、provider、progress、recovery 合同 |

## 使用场景

### 会议回顾

音频、普通录屏或 Teams 录像与 VTT/DOCX 进入同一主旅程。系统先形成可播放逐字稿和人物轮次，再生成语音草稿、画面解读、正式纪要和会议脉络。用户可以按人核听、回到原声/画面、修正原文，并从安全检查点恢复失败阶段。

### 产品视频、发布会和讲解视频

公开链接或本地视频使用媒体 profile：重点是论证结构、规格/图表证据、演示片段和第一手来源，不伪造会议待办。动态镜头和口播需要不同于共享幻灯片的视觉策略；当前属于工作原型，仍需更多内容类型验证。

### 人或团队的知识交付

处理结果可作为一次性离线交付、通用 AI 的来源材料或下游知识库文档。跨会议能力只应围绕用户显式建立的会议序列和问题集，不自动生成永久人物性格、领导画像或组织判断。

### 实验性 Live Context

Live Context 的任务是在会议或直播进行时持续编译可回顾上下文，而不是另做一个实时字幕产品。直播活动默认“后台分析”，会议默认“会议伴随”；文字、人物和画面都保持暂定与 provenance，结束后经 reconcile 和延迟视觉补完才进入现有输出。当前只对无 DRM 原生 HLS 后台路径有可执行实现；browser 和 meeting audio 仍是明确受限的适配器。

## 三类输出

### MeetingPack

给人阅读和核听的自包含离线包。它可以携带 Viewer、逐字稿、纪要、人物、画面、证据和可选压缩媒体，不需要服务器、模型或 CDN。

### AI Context

给用户自行选择的 GPT、Gemini、Notebook、豆包或本地模型使用的中立 Markdown/Pack。它保留证据编号与时间，不携带本机深链和媒体二进制；外部上传由用户确认政策与脱敏范围。

### KB projection

给 WeKnora 或其他知识消费系统的 Markdown/HTML 投影。会议系统负责身份、证据和画面筛选；下游负责分块、索引、检索和问答。知识库不是事实真源。

## 稳定核心

1. **Identity**：回答“谁说的”。本场说话人、导入姓名、跨会声音候选和人工确认分层保存；高风险修改先预览并可撤销。
2. **Evidence**：回答“依据是什么”。纪要 claim 通过稳定 T/P/C 引用回到逐字稿、原声和画面；画面只能证明展示内容，不能独立证明会议决定。
3. **Correction**：回答“错误如何被安全修正”。人工修改不会被自动推断覆盖；revision 让旧纪要、翻译、脉络和索引诚实 stale。
4. **Portable Context**：回答“谁继续使用”。同一 canonical 事实可投影为 Web、Viewer、AI Context 和 KB 文档，不锁定单一消费模型。

## 模型增强层

| 能力 | 作用 | 可替换边界 |
|---|---|---|
| ASR | 从声音形成带时间的原语言文本 | native 或兼容 provider；Context 能力可降级 |
| Speaker diarization | 区分声音轮次并支持人物核听 | 人工确认优先，短片段和重叠语音存在限制 |
| VL | 读取幻灯片、表格、图表和关键画面 | 页面结果是证据来源之一，不直接生成决定 |
| Text generation | 草稿、正式纪要、脉络、翻译和问答 | 输出必须经过结构、引用与 revision 校验 |
| Embedding | 多语言语义召回 | 可关闭并退化为词法检索 |
| Reranker | 对候选证据重新排序 | 不生成事实，只改变候选顺序 |

## 成熟度矩阵

| 能力 | 成熟度 | 说明 |
|---|---|---|
| 会议回顾、人物核听、证据回跳 | 已真实验证 | 真实试用驱动过多轮迭代，仍非正式生产服务 |
| MeetingPack | 已真实验证 | 可离线阅读和核听 |
| 渐进处理与失败恢复 | 已实现，仍在验证 | 合成旅程完整，需积累更多真实失败样本 |
| 媒体视频分析 | 已实现，仍在验证 | 内容类型与质量矩阵仍不足 |
| AI Context / KB projection | 已实现，仍在验证 | 合同可用，消费效果需按下游评测 |
| 单场 RAG | 已实现，仍在验证 | 有 evidence hybrid 检索，缺系统答案评测 |
| 跨会议知识 | 实验中 | 仅对显式序列和固定问题有意义 |
| 多人部门服务 | 当前不在范围 | 缺完整 SSO、ACL、租户与运营机制 |
| Live Context | 实验中 | 原生 HLS 可后台运行；browser 静音捕获、实时延迟和说话人质量尚未在目标主机验证 |

## 产品不是什么

- 不是 Teams、DingTalk 或任一成熟 SaaS 的替代品。
- 不是已经完成的自治 Agent 或部门级知识平台。
- 不是通用 Notebook、Wiki、搜索引擎或互联网监控系统。
- 不是对所有会议自动正确的“真相生成器”。
- 不是与某个本地模型、GPU 厂商或知识库绑定的演示壳。

## 非目标和边界

- 不静默将私有会议发送到云端。
- 不把视觉页面、组织层级或模型自信度提升为事实权威。
- 不在没有反例、时效和人工确认时固化人物反应模式。
- 不为追求功能数量复制第二套播放器、纪要、RAG 或 Notebook UI。
- 不把单机 PoC 描述为生产级多人服务；生产化需要另行建设身份、ACL、TLS、配额、审计和生命周期。
## Experimental Companion

Companion 验证一个窄闭环：重处理与 canonical 数据留在 X Ultra，手机只做 Connect、Send、Check、Review、Correct。它不是缩小版桌面工作台，也不是已获企业批准的远程部署方案。

首个原型通过私有 Tailscale tailnet HTTPS 接入 localhost FastAPI，并在 tailnet 身份之外要求 5 分钟一次性应用配对。移动端只获得最近项目、处理状态、议题、人物、重要结论、证据媒体和人物确认的安全投影；删除、清理、模型配置、重转写、批量导出和管理 API 均不开放。
