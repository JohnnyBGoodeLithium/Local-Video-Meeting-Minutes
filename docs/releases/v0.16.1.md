# Local Video Meeting Minutes v0.16.1

## English

### Highlights

- Structured local image observations render tables and chart values consistently, with unread regions and disagreements visible.
- Screenshot retention is separate from per-pass analysis budgets. Existing transcripts can be reused for visual enrichment.
- Optional shared text/vision endpoints avoid loading a second copy of the same model. Live uses a bounded, independent visual worker.
- Includes assistant editing, queue controls, speaker binding repairs and bundled diarization model updates since v0.16.0.

### Compatibility and migration

Old minutes remain readable. Legacy image descriptions are not trusted as current structured observations: the next visual enrichment reads those images again. Re-extract older capped video timelines to recover missing screenshots; source media and transcripts are preserved. See [visual processing](https://github.com/JohnnyBGoodeLithium/Local-Video-Meeting-Minutes/blob/main/docs/runbooks/VISUAL_PROCESSING.md).

### Known limitations

Unreadable pixels cannot be recovered reliably. Automatic review remains a candidate, not human verification. Difficult-case model ranking and sustained live latency need representative evaluation. OCR is optional, not an extra mandatory stage. Local inference weights other than bundled diarization remain separately configured.

### Validation

Release gates: `make check`, `make smoke`, `make release-verify`. Synthetic schema/cache/conflict/live tests and a local structured table test cover the new contract; they do not establish universal chart accuracy.

## 中文

### 主要变化

- 本地视觉结构化输出并固定渲染表格与图表数值，未读区域和来源分歧明确展示。
- 截图保留与每轮分析预算分开；补充视觉时复用已有逐字稿。
- 可共享同一文本/视觉模型实例；Live 使用独立、有时限的视觉线程。
- 包含 v0.16.0 之后的助手编辑、任务队列、说话人绑定修复与内置说话人模型更新。

### 兼容与迁移

旧纪要继续可读。旧视觉描述不冒充新的结构化证据，下次视觉补充会重新读取图片。旧视频若受截图上限影响，需要重新抽帧恢复画面覆盖；保留原视频和逐字稿。配置与恢复见[视觉处理](https://github.com/JohnnyBGoodeLithium/Local-Video-Meeting-Minutes/blob/main/docs/runbooks/VISUAL_PROCESSING.md)。

### 已知限制

模糊像素无法保证恢复。自动复核仍是候选，不能代替人工核验；复杂图表模型排名与持续直播延迟尚需代表性评测。OCR 为可选能力，不是必经第三层。除随包提供的说话人模型外，推理权重仍需单独配置。

### 验证

发布门禁：`make check`、`make smoke`、`make release-verify`。新增合成 schema、缓存、冲突与 Live 回归，以及本地结构化表格验证；不据此宣称通用图表准确率。
