# 重大工程变化与事故

本文保存会长期影响架构、数据安全或维护方式的工程经验。普通样式修复和按钮调整不进入这里；当前风险看 [RISKS.md](../RISKS.md)，完整实施细节以 Git 和 [archive](../archive/) 为准。

## Viewer 启动期白屏与浏览器级验证

- 日期：2026-08
- 用户或系统影响：导出包文件完整，但 Viewer 在浏览器启动阶段因脚本错误无法阅读。
- 根因：静态检查无法覆盖真实 DOM 初始化、内联数据和浏览器执行顺序。
- 采用方案：增加隔离 Viewer 生成与 Headless Chromium 启动旅程；把离线、无 CDN 和时间码回跳作为发布门禁。
- 数据 / API / schema 边界：不改变 canonical；Viewer 仍是只读 projection。
- 验证：生成虚构 MeetingPack，在 Headless Chromium 中打开并执行核心交互。
- 剩余限制：浏览器版本差异和超大 pack 仍需抽样验证。
- 关键 commit：以对应版本 Git 历史为准。

## ASR 完成但下游阶段失败

- 日期：2026-08
- 用户或系统影响：昂贵的转写已经完成，但视觉、纪要或脉络失败时，旧流程容易让用户误以为必须从头重跑。
- 根因：任务状态过度依赖最后一行日志，阶段产物和恢复检查点没有成为正式用户合同。
- 采用方案：持久化阶段、可用输出和 checkpoint；恢复优先复用逐字稿、人物、语音草稿和已完成页面。
- 数据 / API / schema 边界：恢复不能覆盖人工 revision；从头 ASR 必须显式确认。
- 验证：构造阶段失败并验证定向 successor、重复恢复抑制和已保留结果可读。
- 剩余限制：少量旧脚本仍通过明确标记的 legacy fallback 投影。
- 关键 commit：`job-progress/v2` 发布链。

## 说话人多对一坍缩与人工身份保护

- 日期：2026-08
- 用户或系统影响：自动相似扩展可能把多个真实人物合并到已命名人员，修改一个名字又扩大错误范围。
- 根因：声音相似度、外部文稿姓名和人工确认没有清晰优先级；简单确认与混声修复共享了过重入口。
- 采用方案：人工锁优先；默认只处理手选片段；系统建议必须主动开启；preview 显示多个结果组、保护项和存疑项；应用后就近撤销。
- 数据 / API / schema 边界：自动流程不得静默改派人工确认轮次；极短片段可以只直接改派，不伪造声音证据。
- 验证：覆盖简单确认、多分组、短片段、保护、失败保留选择和撤销的单元与浏览器旅程。
- 剩余限制：重叠语音和极短插话的声音证据仍有限，需要人工抽听。
- 关键 commit：以人物核对功能版本的 Git 记录为准。

## 下游知识 provider 协议漂移

- 日期：2026-08
- 用户或系统影响：测试替身成功不代表真实知识服务完成；真实服务可能长时间处理中或返回不同状态，造成重复发布或错误删除。
- 根因：早期实现把特定 provider 的返回结构当成通用合同，fake provider 没有覆盖真实异步生命周期。
- 采用方案：引入 provider-neutral `KnowledgeSink`、预检、revision 幂等、状态正规化、回执和显式删除；真实协议单独适配。
- 数据 / API / schema 边界：远端不是 canonical；凭据和 target 仅服务端；远端结果不得反写会议事实。
- 验证：使用虚构文档测试创建、等待、更新、失败和删除状态。
- 剩余限制：不同 provider 版本与权限配置仍需真实受控验证。
- 关键 commit：知识发布与恢复相关 Git 历史。

## `job-progress/v2` 取代双重日志推断

- 日期：2026-08-31
- 用户或系统影响：用户过去难以判断当前步骤、哪些结果已可用、是否等待资源以及失败后重跑范围。
- 根因：后端从 stdout 推断 stage，前端又从最后一条自然语言日志推断展示，两者都不是稳定合同。
- 采用方案：发布结构化动态 phase plan、可用输出、ETA 范围、failure taxonomy、retry options 与 attempt history；日志仅作诊断和旧任务回退。
- 数据 / API / schema 边界：progress 不包含正文、人名、路径、原始 URL 或凭据；失败只暴露脱敏 diagnostic ID。
- 验证：不同 route、等待、降级、失败、恢复、刷新持久化和 Headless 旅程。
- 剩余限制：旧作业缺少历史阶段事件时只能显示低精度 legacy 状态。
- 关键 commit：v0.15.0 发布链。

## Canonical、revision 与 projection 边界收敛

- 日期：2026-08
- 用户或系统影响：逐字稿、人物、纪要、Viewer、AI Context、知识库和 RAG 若各自保存“最新版”，会产生互相竞争的事实。
- 根因：早期 PoC 把部分模型产物直接当成最终数据，来源修改后的过期规则不完整。
- 采用方案：明确 canonical transcript、identity、minutes/evidence 与 facts；所有 Viewer、导出、脉络、翻译、索引和 KB 文档绑定来源 revision。
- 数据 / API / schema 边界：projection 不反写 canonical；旧 revision 可以保留恢复但不能展示为当前；写入原子化并保留快照。
- 验证：逐字稿/身份修改后 stale、快速同步、导出刷新与 RAG 拒绝旧引用。
- 剩余限制：部分历史会议只具备兼容 projection，没有完整新 revision 元数据。
- 关键 commit：各 canonical/revision 迁移版本 Git 历史。

## 公开仓库、路径和私有汇报边界

- 日期：2026-08-31
- 用户或系统影响：真实会议、人员、组织、绝对路径或个性化汇报一旦进入公开 Git 历史，难以彻底撤回。
- 根因：产品验证依赖真实本地资料，而早期文档同时承担当前状态、交接和个人汇报。
- 采用方案：公开文档只使用抽象角色和虚构 fixture；个性化报告进入 ignored `private_reports/`；提交前验证 tracked 范围与 Markdown 内容。
- 数据 / API / schema 边界：私有报告、会议数据、日志、模型输出和凭据都不是仓库资产。
- 验证：文档门禁检查 ignore、tracked 路径和公开链接；人工检查语义敏感信息。
- 剩余限制：自动敏感词规则无法理解所有上下文，发布前仍需人工审阅。
- 关键 commit：文档体系重构提交。
