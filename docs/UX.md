# UX 合同

本文回答稳定的用户任务、信息层级、保守默认与可逆交互。适合产品和前端修改；不记录每次按钮调整、实施过程或当前周计划。详细数据边界看 [ARCHITECTURE.md](ARCHITECTURE.md)，当前成熟度看 [STATUS.md](STATUS.md)，旧专项规格见 [archive](archive/)。

## 核心用户角色

- **Reviewer**：浏览结构、搜索内容、按人物回听并核对原声/画面。
- **Meeting preparer**：确认人物、修正逐字稿、恢复失败、导出或发布结果。
- **Technical maintainer**：检查服务、资源、provider 和恢复边界。

普通 reviewer 不需要理解 voice ID、聚类、模型端口、canonical schema 或索引。高级修正和运维入口按任务渐进披露。

## 主工作台层级

1. 顶部只保留产品、全局导航和设置。
2. 左侧承载导入、当前任务、内容列表、搜索和排序。
3. 当前内容标题下只显示一条权威的处理、就绪或失败状态。
4. 播放证据区保留播放器、时间线、人物导航和逐字稿。
5. 阅读区会议默认使用“会议脉络 / 会议纪要 / 画面与资料”；媒体使用“论证脉络 / 分析纪要 / 画面解析”。
6. AI、证据、人物核对、处理详情和恢复详情按需进入同一 side-sheet 体系，但业务状态相互独立。

页面依靠排版、留白和位置建立层级，减少重复边框、状态 chip 和“每个控件一个盒子”。正常完成状态低权重收敛；警告和失败才使用显眼状态色。

## 导入

- 会议接受音频、录屏及可选 VTT/DOCX；媒体接受本地视频或受限公开链接。
- 导入入口先让用户选择任务场景，再显示相关输入，不平铺全部技术格式。
- 视频处理提供两个面向结果的选择：“快速纪要”跳过画面理解，但仍生成正式纪要和会议脉络；“完整分析”在逐字稿和语音草稿可读后继续理解画面并生成多模态结果。
- 快速纪要完成后可从会议状态或“画面与资料”补充画面分析；补充期间复用媒体母版、逐字稿、人物和已有逻辑页，原结果保持可读，不重跑 ASR 或说话人。
- 外部逐字稿可能语言错误或质量不足时，用户可以明确忽略并改用本地 ASR。
- 上传、下载和固化期间必须说明来源状态，不把内部路径或原始 URL 暴露到普通界面。

## 渐进式处理

用户首先需要知道四件事：现在在做什么、什么已经可用、还要多久、出错后怎么办。

- 标题 banner 表达当前业务阶段、第一份可读结果、完整结果和可信 ETA 范围。
- 左侧任务卡在会议标题下直接说明具体动作，例如“构建会议脉络”或“将会议纪要翻译为英文”，再显示全局队列位置或当前进度；不能让不同作业只剩相同会议标题。完整阶段、耗时、attempt 和恢复范围进入详情 sheet。
- 逐字稿或语音草稿形成后立即允许阅读、播放、搜索和核听快照导出；视觉与终稿继续。
- ETA 没有依据时显示“正在估算”，不制造均匀百分比或精确倒计时。
- `waiting_resource` 不是失败，等待时 ETA 不递减；可选增强失败不把整场标红。

## 播放器、时间线与逐字稿

- 播放器和逐字稿在所有阅读任务中保持上下文连续。
- 点击时间码、证据或轮次定位播放，并把目标保持在可见区域中部；不让页面滚动后找不到进度条。
- 选中人物只改变选择和高亮，不暗中切换播放模式。
- “顺次播放”时上一段/重播/下一段走自然时间线；只有明确选择“仅听此人”才跳过其他人物。
- 没有预选人物时，“仅听此人”使用当前播放轮次的人物。
- 长发言按可核听段落导航，下一段不能越过同一长发言的剩余文本。
- 人物颜色用于姓名标签、时间车道和当前句弱高亮，不铺满每一行背景。

## 人物确认

点击人物 chip 先打开非阻塞身份卡，回答“这个声音是谁”：

- 展示本组段数、总时长与最多三个前/中/后代表片段；
- 搜索已有人员、新建人员或稍后处理；
- 简单整组确认最多三次点击完成；
- 普通文案不出现声纹、voice ID、聚类、质心或具名。

只有用户明确指出“这组里混入了其他人”时，才进入高级修复。

## 混声修复

1. 逐字稿只突出当前声音组，用户选择少量“明显不是此人”的样例并试听。
2. 默认只处理手选片段；“同时处理系统找到的相似片段”必须主动开启。
3. preview 展示手选、建议、人工保护、存疑、极短片段和预计新分组。
4. 多个结果组可以分别选择已有人员、新建人员或保持待确认，不强迫所有错误轮次属于同一个人。
5. 应用前显示修改前后段数和时长；人工确认身份由后端强制保护。
6. API 失败保留选择；成功返回原播放时间和滚动位置，高亮变化轮次并就近提供撤销。

## 会议纪要

- 会议脉络是第一眼结构入口，会议纪要是正式阅读文档，画面与资料用于理解和核查。
- 会议脉络优先高度归并为少量整场议题；3–8 个只是推荐浏览密度，不是数据截断合同。复杂多议程内容可以保留更多独立议题，但时间窗、说话人、页面或分享轮次本身不能成为一级议题。
- 语音草稿明确标注画面与数字仍在补充，不开放会制造冲突的正式编辑能力。
- 自然语言可以询问、重组阅读视图或修改正式纪要；意图由服务端规则和 preview 区分，用户不需要先理解技术模式。
- 重组视图不覆盖 `minutes.md`；正式修改经过 evidence 与 revision 校验，并保存可恢复上一版。
- 逐字稿修正后显示“快速同步纪要”。它只复用完整视觉缓存；缓存不足时引导标准重生成。

## 证据回跳与关键结论核对

- 纪要结论显示自然语言依据和时间，点击回到原声、逐字稿与对应画面。
- Focus 可以联动脉络、结论、逐字稿和画面；选择右侧语义节点不自动打断播放，显式时间操作才 seek。
- “核对关键结论”不是永久一级 Tab。只有重点结论待核对、既有判断有问题或 evidence 过期时才出现入口。
- 核对只记录“正确/有问题/无法判断”等人工 evaluation，不调用模型或直接修改正式纪要；发现问题后再进入逐字稿、证据或纪要修正闭环。

## 画面与资料

录屏逻辑页、动态画面、现场照片、白板、纸面笔记和实物照片统一进入“画面与资料”。

- 选择照片后先展示缩略图、文件名、大小、读取状态和建议位置，再询问定位。
- 从资料页进入默认未定位；从播放器“在当前时间添加”进入才默认当前播放时间。
- EXIF 只产生“建议位置”；用户确认后才成为“已定位”。文件 mtime 不冒充拍摄时间。
- 导入前可逐张移除；导入后可看大图、修改显示标题、定位到当前时间、取消定位和删除。
- 新导入资料在安全固化后按批次进入本地视觉分析；列表明确区分排队、分析中、已就绪和失败，失败项可就地重试。
- Vision 只读取图片本身并产出可见内容解读；已确认时间定位只用于把附近逐字稿作为纪要上下文，不反向诱导图片识别。
- 已有终稿优先复用现有视觉缓存快速同步纪要；仍在处理的会议由后续终稿自然吸收资料，不为照片重跑 ASR 或人物区分。
- 顶部一次说明可信边界：现场资料补充上下文，未经发言或人工确认不单独作为决定依据。

## 失败与恢复

失败界面按顺序回答：哪一步没完成、为什么、保留了什么、现在还能做什么、推荐下一步。

- 主操作使用具体文案，如“从第 13 个画面继续”，不使用孤立“重试”。
- 恢复 preview 列出将复用和将重跑内容、预计时间和边界；低风险定向续跑可以减少层级。
- 默认顺序：最近检查点 → 仅失败阶段 → 低资源模式 → 降级完成 → 高质量模型 → 从头重跑 → 更换来源。
- 原任务与 successor 显示为同一任务的多次尝试；恢复成功后旧失败收起但历史可查看。
- 原始日志、脚本、端口和 traceback 不进入普通界面；复制诊断采用脱敏白名单。
- 主要恢复和删除流程使用产品内 sheet/dialog，不使用浏览器原生 `alert/confirm`。

## 导出与知识库

- 普通导出只让用户选择“离线 Viewer”或“AI / 知识库 Pack”两个消费意图；媒体只在 Viewer 需要时选择无媒体、压缩音频或压缩视频。
- 导出是只读 projection，不重写 canonical。包名携带版本和时间，重复导出不覆盖。
- 发布到知识库先预检目标、profile、revision 和预计结果；凭据不进入浏览器。
- 知识库写入不改变逐字稿、身份或 evidence；来源变化后按 revision 更新/替换。

## 跨界原则

### 渐进披露

先呈现用户任务和结果，再按需展示技术状态。简单确认与复杂修复不共用一个大弹窗；普通阅读不展示管理后台和 provider 参数。

### 保守默认

默认最少重算、最低资源、最小数据影响：手选优先、检查点优先、本地优先、不自动扩展、不静默上云。

### 写入前预览

影响多轮人物、正式纪要、canonical 逐字稿、媒体母版、来源文件或隐私边界的操作必须先说明范围。

### 写入后撤销

人物和文本修正提供就近撤销；正式纪要保留历史。无法安全撤销的照片删除使用明确产品内确认并说明影响。

## 双语与无障碍

- 新增或修改的工作台/Viewer 文案同批提供中英投影，使用同一 DOM 和状态数据。
- 按钮、状态、sheet、错误和空状态不能只完成一种语言。
- 键盘可进入主要操作；sheet 管理 focus 并关闭后返回触发点。
- 状态不只依靠颜色；动态进度克制使用 `aria-live`，阶段变化和失败才增强播报。
- 图标按钮有 `aria-label`，选中状态和当前阶段使用结构化语义。

## 仍需观察

- 小屏幕上播放器、逐字稿和阅读区的空间分配仍需真实设备验证。
- 媒体论证脉络、口播折叠和复杂图表的浏览效率尚缺足够样本。
- 条件式关键结论核对是否产生足够用户价值，需观察真实使用频率。
- AI rail 与主阅读区的长期职责仍需防止功能膨胀。
- 多用户、LAN 和知识库权限不属于当前工作台的已完成体验。
