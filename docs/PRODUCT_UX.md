# 产品与交互规格

## 产品定位

主任务不是“启动一条处理管线”，而是打开一场已经处理好的会议，阅读纪要、回到逐字稿核对证据、继续追问，并修正记录。导入、重生成、模型选择和人员配置都是次级任务。

界面遵循三个原则：内容优先、自然语言优先、写入可逆。用户不需要理解模型、diff 或作业路由，也不会因为打开助手而失去纪要上下文。

产品内置 `/product` 介绍页，用同一套内容服务管理者的概念理解、产品/UX 评估和技术架构沟通。页面以“会议机只能识别设备、无法识别现场真实人员”为首要场景，将 Meeting Identity Core、Evidence Core 和 Knowledge Core 作为三条产品主线；不读取或展示任何真实会议、人员或组织数据。

## 当前信息架构

- 顶栏“中文 / EN”控制整套阅读语言：界面导航、状态文案、会议纪要、会议脉络以及屏幕标题/短摘要同步切换。终稿 ready 后后台以最低优先级自动生成另一种阅读语言；旧会议在首次打开时懒补齐。切换语言在原位更新，不重置播放时间、Focus 或阅读位置。脉络翻译只改全场摘要、议题和节点文本，屏幕翻译只改标题和短摘要；ID、时间、证据关联和完整 VL 详情不变。逐字稿保留独立的“原文 / 译文 / 对照”手动控制，避免为了切换界面强制翻译整场逐字稿。
- 左栏：会议搜索与可读会议列表；导入入口收敛在顶部，支持单个音视频，或一次选择 Teams 录像 + 一个 VTT/DOCX 逐字稿。文件名无需完全一致；显式限制一份逐字稿，防止 VTT/DOCX 并存时静默配错。处理队列只在有活动作业或近期失败时出现。运行项显示当前阶段，等待项显示实际队列序号并可点“优先”；优先只改变尚未开始的顺序，不中断当前任务。失败项说明失败类别、已保留资产和建议动作：存在安全检查点时只恢复翻译/纪要/脉络等对应阶段，早期导入失败则要求重新导入；默认不自动切换或加载更大模型。1024px 及以下改为由顶栏“会议”按钮打开的抽屉，不再挤压阅读区。
- 会议库时间与逐字稿来源：列表默认按“最近导入”排序，可切换“会议时间 / 最近更新”并在浏览器中记住。若外部逐字稿不可信，导入设置可选“忽略附带逐字稿”：文件仍作为受保护母版保留，canonical 逐字稿改用本地 ASR。已处理的视频会议可在“更多 → 忽略当前逐字稿·本地重转写”发起同一流程；弹窗必须提示本地 ASR 可能丢失导入姓名，并明确原文件与可恢复快照都会保留。
- 工作台标题：会议名称、日期、时长、发言人数和逐字稿段数，并用“资料 / 证据 / 分享”三个用户状态说明是否可阅读、可核证和可导出。标题旁的“✎ 改名”就地编辑会议名称（Enter 保存、Esc 取消，乐观更新失败回滚）：名称写入会议目录的 `meta.json`，不改目录 slug；名称属于翻译语境 revision 的一部分，改名后既有译文按过期处理、重新进入时再生成。
- 左侧播放证据栏：播放器和时间轴常驻其顶部，逐字稿在同一列连续滚动；点击时间码、来源或整轮任意位置直接定位播放，选中文字时不触发跳转以保留复制能力。逐字稿工具条内置搜索框：大小写不敏感的包含匹配命中整轮并高亮，当前命中加深，Enter / Shift+Enter 在命中间前后跳转并滚动到可见，切换会议时清空。逐字稿可切换原文、译文和对照，并独立选择中文或英语目标语言。820px 及以下轮次改为两行（时间码 + 说话人 chip 上行、正文下行），逐字稿工具条允许折行，模式按钮与“译为”下拉保持可用；播放证据栏整体改为纵向弹性布局，逐字稿获得约四成的保底高度，不再被播放器、时间轴与图例栈压没。
- 右侧会议阅读区：与播放证据栏并排，保持足够正文宽度；分隔条可拖动并保存比例。通过“会议脉络 / 会议纪要 / 屏幕内容 / 结论审计”四个页签，在整场结构、正式记录、屏幕原始资料与人工核证之间切换。合格的会议脉络是理解入口，会议纪要仍是正式记录；脉络缺失、不合格或仍在生成时默认回退纪要。
- 视频默认以紧凑高度出现，可随时展开。时间线固定两条车道：上层是整场 Topic Map 的一级议题区间，同一议题跨多个非连续时间出现时显示为多个同色区间；生成端要求全场覆盖，弱价值内容归入浅色弱化的“过渡与杂项”议题，真正的无发言空档才显示为灰色间隙块、点击只跳转播放。下层是说话人节奏条：按像素桶渲染，每桶染该时间窗发言占比最高者的颜色，桶数与会议长度无关所以永远不碎，点击 seek、悬停显示该位置的发言构成。hover 议题块展示议题摘要，点击议题区间会切换播放进度并定位右侧脉络；点击右侧议题或子节点只建立语义聚焦，不改变正在播放的时间，只有明确的“从这里播放”才 seek。共享 Focus 会持续标出对应时间范围、逐字稿、结论和当前屏幕，直到用户选择另一议题或时间。时间轴下方的人物图例（色点 + 姓名 + 发言占比）按发言占比降序分配颜色并排序，直接显示前 6 名或占比 ≥5% 的人，其余收进“其他(N)”；未绑定声纹的人（会议机拆出的“声音K”等）不参与配色，以灰色斜纹固定沉底并直接提供“绑定”入口。车道区块右下角的“说话人视图”独立按钮可展开/收起逐人车道（收起时按钮也常驻）：每人一行只画该人的发言块，默认展开前 5–6 人，行尾可展开其余。人物 chip、车道姓名或发言块可选择该人；选中后出现“顺次播放 / 仅当前说话人”范围开关，以及上一段、重播本段、下一段和取消选择。仅当前说话人模式会在一段结束后自动跳过他人发言；顺次播放仍保持完整会议音频。没有选中人物时，上一段、重播本段和下一段按整场轮次工作。悬停仍只做临时隔离预览，不改变播放范围。在线工作台保留语义 Focus 摘要供结论审计，离线 Viewer 删除人物区与搜索区之间重复的摘要条，把空间留给直接回听控制。选中的一级议题把分支详情内联展示在该议题正下方（议题色左边框），不再沉到整张脉络图底部造成“展开后看不见”。一级议题按序号从独立调色板取色，时间轴区间块与右侧脉络的“议题 NN”标签同色；同一说话人的颜色在图例、车道和逐字稿说话人 chip 左边框间保持一致。逐字稿中超过约 90 秒或 500 字的单人长发言在句子边界分为约 45 秒/200 字的核听段落；后续段重复显示说话人，并用“同一发言 · N/M”说明归属。可见段落拥有独立的近似起止时间，上一段、重播本段、下一段、播放高亮和“仅听此人”都按这些段落导航，不再一次越过整条长发言。
- 发言回听遵循单一状态契约：人物标签/车道的选中只表示高亮人物并为个人模式预备目标，不会暗中改变逐段导航。只要“顺次播放”高亮，上一段、重播本段、下一段都按整场自然时间线；只有“仅听此人”高亮时，三个动作和自动续播才过滤为该人物。没有预选人物也可以直接点击“仅听此人”，系统以播放器当前位置的轮次确定人物；若当前正在播放此人，不倒回句首。
- 按人回听只接受可解释的本场聚合依据：已绑定声纹可选择并代表跨会议稳定人员；VTT/DOCX 明确姓名即使没有声纹绑定，也可在本场按完全同名聚合跳播；未命名但已形成 `voice_id` 的“说话人 K”可按该声音簇跳播，并保留补充姓名/绑定入口。这两类本场依据都不生成稳定 `person_id`。只有声音过短、未形成可用声音簇时，人物 chip、车道及“仅听此人”才显示禁用状态与禁止光标。
- 右侧智能栏：默认收成右下角紧凑入口，打开后以“AI 对话 / 证据”页签共用同一侧栏。宽桌面停靠，较窄桌面覆盖阅读区但不弹模态，手机使用工作区内全宽侧页；纪要依据显示第一条原文时间码，点击一次即跳到该位置播放并打开完整证据，后续原文仍可逐条切换。AI 对话的回答是流式逐段呈现的（先出证据、再逐段出字），长回答不必整段等待。
- “更多”：重新生成、全文优化、离线查看包导出、人员与高级设置等低频能力。
- “存储与清理”：按原始母版、阅读资产和可再生缓存展示逻辑占用。智能清理明确列出 PCM 工作音轨、VL 高分辨率工作帧和 RAG 索引，只删除可重新生成项；母版、逐字稿、纪要、Topic Map 与逻辑页面不进入该按钮。导入完成后项目母版与下载源相互独立，成功作业的上传暂存自动清理。
- `/admin`：人员身份、声纹试听/绑定、图形化组织架构和参考文件。

## 人员、声纹与组织架构

人员身份、声音证据与岗位节点是三个不同对象：人员使用稳定 ID；一个人员可以挂多条声纹，也可以对应一个组织架构节点。中文名、全拼、英文名加姓氏、Org Chart 原名等作为经过确认的类型化名称保存在同一人员下，并由该人员独立选择首选显示名。

- 姓名只有在唯一精确命中已确认名称时才可自动绑定；包含、拼写相近或跨语言相似只作为候选。
- 新名字必须由用户显式选择“新建人员”，随后可补全类型化名称；不会因为相似度被强行归入既有人。
- 声纹列表和确认弹窗都提供试听；候选人若已有声音，可做 A/B 试听后再确认。
- Org Chart 采用适合大组织的纵向可折叠层级画布：多个根节点自动换列，超过 40 人默认折叠到一级，搜索时展开匹配路径。选择节点后在卡片下方显示新增下属、编辑、设为根节点和删除等快捷操作；也可拖到另一节点设置上级，或拖到根区域取消上级。拖动不弹确认，立即进入可撤销的本地草稿，只有点击保存才写入。服务端拒绝不存在、自指或循环的汇报关系。
- 人员身份与岗位节点分离。未进入 Org Chart 的人员显示在待放置区，可拖入画布；提取草稿只增量补充空字段和新节点，不覆盖已确认上级。
- 卡片显示的是 `manager_id` 对应的直属人数，不是全部后代；直属人数达到 30 时标记为待检查的过平关系。删除有下属的节点只删除该节点，其直属下属提升到原上级（或根层）。结构操作会清除搜索过滤，并展开目标到根的完整路径，避免残留搜索或祖先折叠造成“全部消失”的错觉；无搜索结果时也提供明确的“清除搜索”按钮。
- 改首选显示名会同步既有逐字稿中的关联说话人标签；既有纪要不静默改写，后续重新生成时使用新名称。
- 两位声音相近的说话人被并入同一声纹时，可以按轮拆分：点击说话人 chip 打开绑定弹窗，选择“有些轮次不是 TA → 逐轮标记拆分”进入标记模式——该说话人的轮次高亮为可标记，逐轮点击标记/取消，**只需标出少量样例**（长会议不必逐条找全）：服务端以标记轮次建立新簇质心后，会把该声纹本场其余全部轮次按声纹相似度“离谁近归谁”自动重排。底部常驻的橙色操作条显示已选数量；在操作条的“具名为”输入框填入已知人员姓名可一步拆分并具名（留空则拆分出声纹保持未绑定），点“确认拆分”并确认后生效。服务端只对所选轮次的音频段重提声纹嵌入并贪心聚类（所选轮次可能不止一个人），逐簇匹配库内其他声纹或匿名新建待绑定；原声纹质心自动用重排后剩余轮次重算校正，避免继续被混入的发音污染。若选中的声纹在本会议只有一两轮且被全部选中（同名碎片声纹），拆分无意义：操作条填“具名为”即整体改派，或点说话人 chip 直接绑定。拆分失败或请求异常时标记保留并明确提示，可重试。

## 逐字稿引用交互

引用是结构化证据，不等于修改目标。

用户可以：

1. 在某一轮右侧点击“引用”；
2. 用鼠标跨多轮选择文字，再明确选择“问助手”或“用这段更新纪要”；
3. 重复添加多段不连续引用，并逐张移除。

引用卡展示时间范围、说话人、轮次数和短预览。点击引用卡会跳转播放器并高亮对应逐字稿。浏览器只发送轮次索引和逐字稿 revision；服务端从正式文件重新取内容。

## 逐字稿翻译与核对

翻译是逐字稿的阅读层，不是新的事实来源。原始 `transcript.spk.json` 永不被翻译覆盖。

- “原文”只展示转写结果；“译文”形成所选目标语言的连续阅读层，并提供单轮原文展开；“对照”同时展示原文和译文。原本就是目标语言的轮次不重复显示。
- “译为”与阅读模式分离，可选中文或 English。纯中文会议默认推荐英语，纯英文会议默认推荐中文；混合会议沿用用户选择。切换目标语言读取独立 sidecar，不覆盖另一种译文。
- 首次进入译文/对照时创建后台翻译作业。翻译按连续轮次分批，并携带前后语境、已确认人员名称、当前页面和与这些 T ID 直接关联的结论。
- 每批完成后立即显示其中的完整轮次，未完成轮次继续显示原文和“等待翻译”；不展示半句话或 token。新增内容时锚定当前可见 T ID，避免滚动位置跳动。
- 关联结论只用于主题、术语和指代消歧，不能把结论存在但当前发言没有表达的信息补入译文；翻译必须保留否定、保留意见和 suggest/prefer/expect/approve/decide 等表达强度。
- 从纪要点击“依据”时，即使用户仍在原文模式，也会把证据轮次及前后各一轮临时展开为对照，并把对应批次放到翻译队列最前。翻译过程中播放到尚未完成的轮次，也会动态提升该批次优先级。
- 标题栏显示阶段、完成轮次/总轮次和进度条。用户可以停止；已完成轮次继续可读。继续或失败重试复用同 revision 的已有结果，只处理缺失轮次。
- 每种目标语言的翻译 sidecar 都与逐字稿和会议语境 revision 绑定。逐字稿、说话人或相关背景变化后旧译文不再展示，用户重新进入译文模式即可生成新版本。
- 翻译作业与其他模型作业共用串行队列，避免本机资源争抢；默认位于新会议处理和纪要/脉络任务之后，用户仍可手动置顶。处理中可正常阅读原文、播放和使用已有纪要。

当前暂不包含术语表编辑和单轮人工改译。先验证“浏览纪要 → 点击依据 → 对照核对 → 继续阅读附近逐字稿”的行为旅程，再决定修正入口放在单轮菜单还是统一术语工作区。

## 询问流程

0. 每场会议的对话保存在本浏览器 localStorage（上限 50 条消息 + 8 轮上下文），刷新或重开浏览器后按逐字稿 revision 匹配恢复；逐字稿或身份变化后旧对话与引用自动作废，服务端重启后未写入的修改预览卡在应用时会明确报失败。
1. 用户直接输入问题，引用逐字稿是可选操作。
2. 有显式引用时，助手优先使用引用及其相邻轮次；没有引用时并行执行词法与多语言稠密检索，再经过融合和 reranker。模型服务异常时无感降级到词法检索。
3. 回答中的 `【T1】` 等来源可以点击，定位到原始时间和逐字稿，同时在智能栏切到证据页核对原文。
4. 证据不足时应明确回答“不知道”，不能补写会议事实。

## 修改纪要流程

1. AI 输入框同时接受提问和纪要修改，不要求用户先选择某种表单或入口；“重组纪要”和逐字稿选区只是意图快捷方式。明确包含栏目、顺序、按人组织或写入/修改语义的自然语言直接进入对应修改流程，其余内容按问答处理。
2. 服务端根据要求与逐字稿证据选择最多四个候选 Markdown 章节。
3. LLM 只能返回一个候选章节的完整替换块。
4. 生成结果先经过 marker 白名单、正式待办语义和 revision 校验；校验失败不触碰正式纪要。
5. 校验成功后直接在 `.history/minutes/` 保存旧版本并原子写入，UI 只显示“已更新”、简短变更摘要和一步撤销。完整写入版本按需展开，使用正常 Markdown 阅读样式，不暴露内部 evidence marker，也不制造多个嵌套滚动区。
6. 用户继续输入自然语言即可再次调整；不再要求先操作“继续调整”按钮。
7. 只有当前纪要仍是该次修改产生的 revision 时才允许撤销，避免覆盖后续编辑。

如果逐字稿或纪要在预览后发生变化，保存或撤销会返回冲突，要求重新生成预览或人工检查。

## 结论审计流程

结论审计用于判断纪要中的结构化结论是否被原文和画面依据支持，不调用模型，也不直接修正文档。

多模态终稿发布时若语音草稿中的重要决定、行动、风险或未决项没有在终稿找到对应证据投影，顶部资料状态显示“终稿待复核”。这不是失败，也不阻止阅读或导出：事项可能被后文纠正、合并或确实遗漏。提示只给出未匹配数量，并把判断动作导向“结论审计”，不在首页制造第二份竞争纪要。

1. 用户选择会议并切换到“结论审计”，默认范围为“重点结论”，只包含非 informational 的决定、共识、提议、正式行动、风险与未决问题；开场、出席、议程、页面事实和普通信息记录保留在“全部证据”，不占用首轮审计队列。
2. 卡片展示结论状态、类型、发言人、逐字稿数量和页面数量；“核对依据”定位左侧原文、录音和画面。
3. 用户选择“正确、提议不是决定、应该是决定、证据不对应、负责人/期限错误、原文没有该信息、暂时无法判断”之一，可附加说明。数字键 1–7 对应七种判断。
4. 每次判断立即写入本机 `evaluations/<meeting>.json`，并更新完成率、问题数和筛选结果；正式纪要保持不变。
5. 评测事件只保存 claim ID、来源结构指纹、标签和备注，不重复保存纪要或逐字稿正文。
6. 指纹覆盖结论及其实际引用的逐字稿/页面来源。相关内容变化时原判断失效；无关段落变化不会让全部结果失效。

首轮审计的目标是发现模型和提示词的稳定失效类型。审计结果不会自动训练或改写 prompt；需要先汇总问题，再由人工确认是否调整策略并运行下一轮对比。

## 三层会议阅读

同一批源数据按阅读目的投影为三层，不重复生成三份相互冲突的事实：

1. “会议纪要”回答整场会议最终讲了什么，以说话人身份、逐字稿、VL 页面和 evidence claim 的整合结果为主，只呈现常规纪要；canonical 文件中为证据/RAG 保留的逐页详情不再重复铺在阅读页底部；
2. “会议脉络”回答整场会议围绕哪些核心议题展开。它以整场会议为根，归并出 3–8 个一级议题；首屏只展示根与一级议题，选中后才展开该分支的背景、观点、约束、决定、行动、风险和待确认等类型化子节点。相同议题在不连续时间再次出现时仍是同一分支。点击分支只建立语义聚焦，时间范围提供显式播放入口。截图、页面变化、时间窗和说话人都只能作为依据，不能直接成为节点；
3. “屏幕内容”回答屏幕上具体展示了什么。左侧以缩略图、标题、时间、信息价值和讨论状态组成资料列表；右侧查看一份完整 VL 解读及全部出现区间。低信息画面默认折叠但不删除；页面只展示而没有被口头讨论时，不能据此推断会议作出决定。当前屏幕可打开沉浸式预览，在 125%–300% 间缩放、双击放大并前后切换逻辑页；切页更新播放时间与共享 Focus，但不自动播放，关闭后回到原阅读位置。

产品内部区分三个概念：`Segment` 是页面或摄像头画面的一次连续出现，`Chapter` 是兼容旧会议的连续讨论时间段，`Topic` 是可跨时间复用的语义主题。右侧脉络和时间线上层以版本化的 `meeting-topic-map/v3` 为准（revision 匹配的 v1/v2 旧图仍可消费）；旧 Chapter 只在 Topic Map 尚未生成且纪要本身有少量明确议题时用于时间导航，不再把几十个视觉 Segment 伪装成章节。

Topic Map 的“依据”与“导航”不能共用一个字段：代表 T/P/C 引用用于解释为什么得到这个观点，导航范围用于回答整场哪些讨论属于这个观点。时间轴展示章节尺度：同一议题之间不超过 60 秒的短回应、过渡或未分类轮次直接归回该议题，不用逐轮分类噪声切碎主议题；不同议题或长间隔仍明确分段。灰色斜纹表示未被章节吸收的过渡/等待，琥珀色表示长段尚未归入任何议题；未知内容不得跨长间隔自动改名为最近议题。脉络根节点显示“已归入议题”的轮次比例，帮助用户发现归纳尺度是否明显遗漏，而不是把静音时长误算成内容缺失。

Topic Map 由本机 LLM 两阶段生成：先按约十五分钟窗口提取候选议题，再从整场视角归并为 3–8 个一级议题和 2–7 个结构子节点。一级议题对逐字稿轮次使用互斥主归属，同一段不会同时铺成两个互相覆盖的时间长条。整场归并只给出代表性时间点时，会沿着“与局部候选共享 turn”的明确锚点继承该候选的完整范围；没有锚点的内容不猜。明确判定的寒暄/等待可进入浅色 `low_value` 分支；只有很短的漏挂片段按时间邻近补入，长段未知内容保留为时间轴缺口并要求重新归纳，不能为了覆盖数字挂到一个语义不匹配的标题。覆盖统计按实际持有的 turn 区间计算，并记录未分配轮次、候选恢复数和去掉的重复引用。全场归并若返回非 JSON，先修语法，再用紧凑候选输入重试，最后才确定性投影局部候选；兜底不会凭空凑足主题或合并无关标题，仍服从 3–8 个一级议题质量门槛。每个节点必须引用现存 T/P/C ID；无有效依据的节点丢弃，决定和行动状态服从 canonical evidence。sidecar 与逐字稿、纪要、页面和 VL 描述 revision 绑定，任一输入变化后旧图不再展示。同一逻辑页离开后再次出现仍生成新的 Segment，因此屏幕层可分别跳转，但只共享一份 VL 解读，不增加 Topic 数量。

## 自然语言重组纪要

用户不需要先选择“周会、1:1、复盘”等模板，也不必先点击专门入口。可以直接在 AI 输入框说“按分享人组织”“先结论与待办，再列风险”“删除背景栏目”等；标题栏“重组纪要”仅作为提示性快捷入口。通过事实与 revision 校验后，整篇结果保存为独立 AI 纪要视图，默认切到新视图，但标准纪要始终保留并可从标题栏切回。局部事实修正才直接写入标准纪要并提供一步撤销；历史存在时还提供跨刷新/重启的“恢复上一版”。完整版本默认折叠，避免在窄栏重复展示多份长文。

这个交互改变的是事实的阅读投影，不是会议事实本身：服务端只允许复用完整事实层已有的 evidence marker；无依据正文、未知 marker、异常循环重复和被错误升级的正式待办都不能通过。同一事实可以合理出现在“总体结论”和“按人/按项目明细”等不同阅读视角，但同一栏目不应重复。会议脉络继续表达会议发生顺序，因此不会随着纪要结构要求重写。这样“按分享轮次”只是可输入的一个真实场景，不是代码里特办的唯一模板。

## 渐进式纪要发布

带屏幕录制的会议不再等待全部 VL 才首次出现内容。语音转写和说话人完成后，工作台自动打开带明显进度条的“语音草稿”；草稿已可播放、搜索、翻译和追问，并明确告知数字、表格和画面语境仍在补充。语音草稿的文本模型请求关闭 thinking，优先保证可读正文；如果草稿仍失败，界面明确解释“草稿失败，正在生成多模态终稿”，绝不继续显示空白“暂无纪要”或误报“草稿可读”。VL 终稿完成后在同一会议中替换纪要，优先按同名标题保留阅读位置，之后再开放编辑、结论审计、Topic Map 和导出。这是两个有版本语义的阶段，不是在用户无感时悄悄改纪要。

## 离线分享

“分享 / 导出”先运行只读预检，展示 evidence 状态、有来源链接的结论数、逐字稿/页面数量、媒体可用性和压缩后预计大小。默认生成不含音视频的 `.meetingpack.zip`；顶层只有 `viewer.html`、`README.txt` 和 `assets/`。Viewer 保留在线工作台的同一信息层级，但采用独立的响应式核听工作台：通过质量门槛时默认打开“会议脉络”，否则回退“会议纪要”，并保留“逐字稿”“屏幕内容”和右侧证据核对。播放器、章节/人物时间轴、说话人选择及逐段回听控制是所有 Tab 共用的左侧工作区；右侧只显示当前内容。进入逐字稿后切换到脉络/纪要/屏幕会立即退出逐字稿，不把一次临时核听固化成三栏状态。顶部入口和搜索位置不随模式移动；右侧内容区在大屏获得约三分之二宽度，脉络按可用宽度自然展开多列。普通脉络节点只展开说明并把详情开头带入可视区，显式时间才改变播放位置；播放跟随把当前发言保持在逐字稿中部。议题时间轴使用冷色系，人物时间轴和姓名标签使用独立的分类色系；普通逐字稿行保持中性背景，只有当前核听句使用很浅的人物色。无视频时，冻结截图作为内容舞台随音频或时间选择切换；音频选项生成 AAC 40kbps 分享版，视频选项生成 720p/10fps 分享版，两者都不修改项目中的原始母版。格式与 RAG 规则见 `docs/EXPORT_AND_RAG.md`。

在线工作台和产品介绍页的顶栏显示产品版本。导出预检在生成前展示产品版本和文件名格式；Viewer 显示实际生成该包的版本。这三处用于验收和沟通，前端构建号只用于缓存排障。

离线包与中心智能版是两个清晰模式：离线包必须依靠导出时预生成的阅读视图、完整逐字稿和证据跳转完成理解；中心智能版由轻量 Viewer 调用有算力机器上的 RAG/LLM。不能要求收件方运行模型，也不能把无鉴权的本机接口直接开放到网络。

MeetingPack v4 已达到上述离线基础目标。会议脉络复用导出时冻结的 Topic Map，不再次让 Viewer 调用 LLM；屏幕标题和详情在进入 Viewer、Evidence 和 RAG 前统一清理 `<think>/<analysis>`。Viewer 同步提供整场逐段回听、选人、仅听此人和个人上一段/重播/下一段，且不依赖服务端。旧纪要缺少 marker 时仍能完整阅读和播放，但会显示 `partial` 告警。导出不会修改会议目录或媒体母版。自由问答仍只属于中心智能版，不会在静态 HTML 中伪造一个不可用的聊天入口。

## 阅读体验 P0（2026-08-12 已实现）

本轮把 2026-08-11 走查的阅读连续性与状态语义落到产品中：

1. 刷新后恢复上次会议、有效 revision 下的逐字稿轮次/纪要标题、语言和分栏比例；内容变化时安全回到顶部；
2. 标题区展示资料、证据与分享状态；证据不足时质量入口改名提示，不伪装成正常验收；
3. 视频播放器提供紧凑/展开状态，逐字稿/纪要分栏可拖动并记忆；时间线拆成播放进度和章节/页面两层；
4. 底部宽助手改为右侧 AI/证据智能栏，并按有无 claim 给出确定性建议问题；
5. 作业面板使用可读会议名、中文阶段和翻译完成量，不再把原始 slug 与英文状态作为主信息；
6. 导出改为预检向导，显示证据完整性、媒体可用性和预计包大小；
7. 1024px 及以下会议库改为抽屉，390px 使用上下阅读布局和全宽智能栏。

本轮又把在线阅读调整为“会议脉络 / 常规纪要 / 屏幕内容”：常规纪要移除重复的逐页详情；整场脉络以 AI Topic Map 展示“会议根—一级议题—类型化子节点”，同一议题可绑定多个时间范围。合格脉络成为第一眼，首屏只展示一级议题，当前分支按需展开；节点选择建立跨播放器/画面、时间轴、逐字稿和结论的共享 Focus，但不改变播放时间，显式时间入口才跳转。屏幕内容列表直接显示缩略图与标题，并区分核心/参考/低信息及讨论状态。页面检测默认排除右侧 15% 参会人栏、抑制稀疏红框/激光点，并对顶部大标题单独增强：讲解标注不新建页，同表格但标题变化仍新建页。导出 Viewer 同步相同三层和 Focus 语义，无视频时用截图内容舞台补足时间上下文。助手回答已改为 SSE 流式（先出证据、再逐段出字）；仍待补停止生成和“检索→核对→组织回答”阶段提示。

同类项目调研、响应式问题、目标架构和分阶段验收标准见 `docs/UX_REVIEW_AND_REFERENCES.md`。
