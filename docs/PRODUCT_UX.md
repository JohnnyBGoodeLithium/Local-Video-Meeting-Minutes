# 产品与交互规格

## 核心任务

用户进入一场会议后，主要完成四件事：回听并核对逐字稿、识别说话人、阅读/重生成纪要、引用会议证据进行问答或修改纪要。

## 当前信息架构

- 左栏：上传、作业队列、会议搜索与会议列表。
- 中栏：逐字稿、时间码跳转、播放跟随、说话人绑定、引用入口。
- 右上：音视频播放器、幻灯片页时间轴与议题标记。
- 右下：`纪要 / 助手` 页签。纪要用于阅读；助手用于带证据问答和修改预览。
- `/admin`：人员/声纹绑定、别名、合并、组织架构和参考文件。

## 逐字稿引用交互

引用是结构化上下文，不等于修改目标。

用户可以：

1. 在某一轮右侧点击“引用”；
2. 用鼠标跨多轮选择文字，再点击浮动的“引用到助手”；
3. 重复添加多段不连续引用，并在助手顶部逐张移除。

引用卡展示时间范围、说话人、轮次数和短预览。点击引用卡会跳转播放器并高亮对应逐字稿。浏览器向服务端发送轮次索引和逐字稿 revision；服务端从正式文件重新取内容。

## 询问流程

1. 用户选择引用（可选）并输入问题。
2. 有显式引用时，助手优先使用引用及其相邻轮次；没有引用时执行轻量关键词/中文二元组检索。
3. 回答中的 `【T1】` 等来源可以点击，定位到原始时间和逐字稿。
4. 证据不足时应明确回答“不知道”，不能补写会议事实。

## 修改纪要流程

1. 用户把操作类型切换为“更新纪要”，输入修改要求。
2. 服务端根据要求与逐字稿证据选择最多四个候选 Markdown 章节。
3. LLM 只能返回一个候选章节的完整替换块。
4. UI 展示目标章节、修改说明和 unified diff。
5. 用户确认后才写入；写入前再次校验纪要 revision，并在 `.history/minutes/` 保存旧版本。

如果逐字稿或纪要在预览后发生变化，应用操作返回冲突，要求用户刷新并重新生成预览。

## 尚未实现的交互

- 流式输出与停止生成；当前请求完成后一次性显示。
- 直接修正逐字稿文本；该能力需要同步 JSON/Markdown、保留人工修订标记，并提示纪要已过期。
- 纪要正文选区作为明确修改目标；当前由服务端从候选章节中选择，也支持 API 的 `target_heading`。
- 跨会议问答和全局向量检索。
- 历史版本浏览/一键恢复；当前只自动保存备份。

这些能力应按顺序推进，不能用“允许模型任意调用文件工具”替代确定性的产品流程。
