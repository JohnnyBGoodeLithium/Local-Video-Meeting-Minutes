# 产品与交互规格

## 产品定位

主任务不是“启动一条处理管线”，而是打开一场已经处理好的会议，阅读纪要、回到逐字稿核对证据、继续追问，并修正记录。导入、重生成、模型选择和人员配置都是次级任务。

界面遵循三个原则：内容优先、自然语言优先、写入可逆。用户不需要理解模型、diff 或作业路由，也不会因为打开助手而失去纪要上下文。

产品内置 `/product` 介绍页，用同一套内容服务管理者的概念理解、产品/UX 评估和技术架构沟通。页面以“会议机只能识别设备、无法识别现场真实人员”为首要场景，将 Meeting Identity Core、Evidence Core 和 Knowledge Core 作为三条产品主线；不读取或展示任何真实会议、人员或组织数据。

## 当前信息架构

- 顶栏“中文 / EN”控制整套阅读语言：界面导航、状态文案、会议纪要和会议脉络同步切换。纪要与脉络译文首次按需生成并在原位更新，不重置播放时间、Focus 或阅读位置。脉络翻译只改全场摘要、论点和节点文本，ID、时间和证据关联不变。逐字稿保留独立的“原文 / 译文 / 对照”控制，避免仅切换界面时强制启动整场逐字稿翻译。逐字稿“译为”目标语言的默认值跟随界面语言（中文界面默认译为中文，英文界面默认译为 English），用户手动选择后不再被界面切换覆盖。
- 左栏：会议搜索与可读会议列表；导入入口收敛在顶部，处理队列只在有活动作业时出现。运行项显示当前阶段，等待项显示实际队列序号并可点“优先”；优先只改变尚未开始的顺序，不中断当前任务。1024px 及以下改为由顶栏“会议”按钮打开的抽屉，不再挤压阅读区。
- 工作台标题：会议名称、日期、时长、发言人数和逐字稿段数，并用“资料 / 证据 / 分享”三个用户状态说明是否可阅读、可核证和可导出。
- 左侧播放证据栏：播放器和时间轴常驻其顶部，逐字稿在同一列连续滚动；点击时间码、来源或整轮任意位置直接定位播放，选中文字时不触发跳转以保留复制能力。逐字稿可切换原文、译文和对照，并独立选择中文或英语目标语言。820px 及以下轮次改为两行（时间码 + 说话人 chip 上行、正文下行），逐字稿工具条允许折行，模式按钮与“译为”下拉保持可用。
- 右侧会议阅读区：与播放证据栏并排，保持足够正文宽度；分隔条可拖动并保存比例。通过“会议脉络 / 会议纪要 / 屏幕内容 / 结论审计”四个页签，在整场结构、正式记录、屏幕原始资料与人工核证之间切换。合格的会议脉络是理解入口，会议纪要仍是正式记录；脉络缺失、不合格或仍在生成时默认回退纪要。
- 视频默认以紧凑高度出现，可随时展开。时间线固定两条车道：上层是整场 Topic Map 的一级论点区间，同一论点跨多个非连续时间出现时显示为多个同色区间；生成端要求全场覆盖，弱价值内容归入浅色弱化的“过渡与杂项”论点，真正的无发言空档才显示为灰色间隙块、点击只跳转播放；confirmed 结论与正式待办在车道上投影为菱形刻度，悬停看文本、点击跳到该结论。下层是说话人节奏条：按像素桶渲染，每桶染该时间窗发言占比最高者的颜色，桶数与会议长度无关所以永远不碎，点击 seek、悬停显示该位置的发言构成。hover 论点块展示论点摘要，点击论点区间会切换播放进度并定位右侧脉络；点击右侧论点或子节点只建立语义聚焦，不改变正在播放的时间，只有明确的“从这里播放”才 seek。共享 Focus 会持续标出对应时间范围、逐字稿、结论和当前屏幕，直到用户选择另一论点、人物或时间。时间轴下方的人物图例（色点 + 姓名 + 发言占比）按发言占比降序分配颜色并排序，直接显示前 6 名或占比 ≥5% 的人，其余收进“其他(N)”；未绑定声纹的人（会议机拆出的“声音K”等）不参与配色，以灰色斜纹固定沉底并直接提供“绑定”入口。图例可展开逐人车道：每人一行只画该人的发言块，点击 seek，默认展开前 5–6 人，行尾可展开其余。点击人物 chip 进入人物 Focus：车道与逐人车道其他人降透明度、该人轮次在逐字稿高亮、摘要显示发言轮数与相关结论，再点一次或“返回整场”取消；人物 Focus 是高亮而非过滤，证据核对不丢失他人语境。同一说话人的颜色在图例、车道和逐字稿说话人 chip 左边框间保持一致。逐字稿中超过约 90 秒或 500 字的单人长轮次在句子边界分为约 45 秒/200 字的显示子块，后续子块以缩进和弱化“继续”标记表示同一轮，点击子块按字符比例插值定位播放。
- 右侧智能栏：默认收成右下角紧凑入口，打开后以“AI 对话 / 证据”页签共用同一侧栏。宽桌面停靠，较窄桌面覆盖阅读区但不弹模态，手机使用工作区内全宽侧页；引用原文或点击依据会自动进入对应页签。
- “更多”：重新生成、全文优化、离线查看包导出、人员与高级设置等低频能力。
- “存储与清理”：按原始母版、阅读资产和可再生缓存展示逻辑占用。智能清理明确列出 PCM 工作音轨、VL 高分辨率工作帧和 RAG 索引，只删除可重新生成项；母版、逐字稿、纪要、Topic Map 与逻辑页面不进入该按钮。导入完成后项目母版与下载源相互独立，成功作业的上传暂存自动清理。
- `/admin`：人员身份、声纹试听/绑定、图形化组织架构和参考文件。

## 人员、声纹与组织架构

人员身份、声音证据与岗位节点是三个不同对象：人员使用稳定 ID；一个人员可以挂多条声纹，也可以对应一个组织架构节点。中文名、全拼、英文名加姓氏、Org Chart 原名等作为经过确认的类型化名称保存在同一人员下，并由该人员独立选择首选显示名。

- 姓名只有在唯一精确命中已确认名称时才可自动绑定；包含、拼写相近或跨语言相似只作为候选。
- 新名字必须由用户显式选择“新建人员”，随后可补全类型化名称；不会因为相似度被强行归入既有人。
- 声纹列表和确认弹窗都提供试听；候选人若已有声音，可做 A/B 试听后再确认。
- Org Chart 采用适合大组织的纵向可折叠层级画布：多个根节点自动换列，超过 40 人默认折叠到一级，搜索时展开匹配路径。选择节点后在卡片下方显示新增下属、编辑、设为根节点和删除等快捷操作；也可拖到另一节点设置上级，或拖到根区域取消上级。拖动不弹确认，立即进入可撤销的本地草稿，只有点击保存才写入。服务端拒绝不存在、自指或循环的汇报关系。
- 人员身份与岗位节点分离。未进入 Org Chart 的人员显示在待放置区，可拖入画布；提取草稿只增量补充空字段和新节点，不覆盖已确认上级。
- 卡片显示的是 `manager_id` 对应的直属人数，不是全部后代；直属人数达到 30 时标记为待检查的过平关系。删除有下属的节点只删除该节点，其直属下属提升到原上级（或根层）。结构操作会清除搜索过滤，并展开目标到根的完整路径，避免残留搜索或祖先折叠造成“全部消失”的错觉；无搜索结果时也提供明确的“清除搜索”按钮。
- 改首选显示名会同步既有逐字稿中的关联说话人标签；既有纪要不静默改写，后续重新生成时使用新名称。

## 逐字稿引用交互

引用是结构化证据，不等于修改目标。

用户可以：

1. 在某一轮右侧点击“引用”；
2. 用鼠标跨多轮选择文字，再明确选择“问助手”或“用这段更新纪要”；
3. 重复添加多段不连续引用，并逐张移除。

引用卡展示时间范围、说话人、轮次数和短预览。点击引用卡会跳转播放器并高亮对应逐字稿。浏览器只发送轮次索引和逐字稿 revision；服务端从正式文件重新取内容。

## 逐字稿翻译与核对

翻译是逐字稿的阅读层，不是新的事实来源。原始 `transcript.spk.json` 永不被翻译覆盖。

- “原文”只展示转写结果；“译文”形成所选目标语言的连续阅读层，并提供单轮原文展开；“对照”同时展示原文和译文。原本就是目标语言的轮次不重复显示。
- “译为”与阅读模式分离，可选中文或 English。纯中文会议默认推荐英语，纯英文会议默认推荐中文；混合会议沿用用户选择。切换目标语言读取独立 sidecar，不覆盖另一种译文。
- 首次进入译文/对照时创建后台翻译作业。翻译按连续轮次分批，并携带前后语境、已确认人员名称、当前页面和与这些 T ID 直接关联的结论。
- 每批完成后立即显示其中的完整轮次，未完成轮次继续显示原文和“等待翻译”；不展示半句话或 token。新增内容时锚定当前可见 T ID，避免滚动位置跳动。
- 关联结论只用于主题、术语和指代消歧，不能把结论存在但当前发言没有表达的信息补入译文；翻译必须保留否定、保留意见和 suggest/prefer/expect/approve/decide 等表达强度。
- 从纪要点击“依据”时，即使用户仍在原文模式，也会把证据轮次及前后各一轮临时展开为对照，并把对应批次放到翻译队列最前。翻译过程中播放到尚未完成的轮次，也会动态提升该批次优先级。
- 标题栏显示阶段、完成轮次/总轮次和进度条。用户可以停止；已完成轮次继续可读。继续或失败重试复用同 revision 的已有结果，只处理缺失轮次。
- 每种目标语言的翻译 sidecar 都与逐字稿和会议语境 revision 绑定。逐字稿、说话人或相关背景变化后旧译文不再展示，用户重新进入译文模式即可生成新版本。
- 翻译作业与其他模型作业共用串行队列，避免本机资源争抢；默认位于新会议处理和纪要/脉络任务之后，用户仍可手动置顶。处理中可正常阅读原文、播放和使用已有纪要。

当前暂不包含术语表编辑和单轮人工改译。先验证“浏览纪要 → 点击依据 → 对照核对 → 继续阅读附近逐字稿”的行为旅程，再决定修正入口放在单轮菜单还是统一术语工作区。

## 询问流程

1. 用户直接输入问题，引用逐字稿是可选操作。
2. 有显式引用时，助手优先使用引用及其相邻轮次；没有引用时并行执行词法与多语言稠密检索，再经过融合和 reranker。模型服务异常时无感降级到词法检索。
3. 回答中的 `【T1】` 等来源可以点击，定位到原始时间和逐字稿，同时在智能栏切到证据页核对原文。
4. 证据不足时应明确回答“不知道”，不能补写会议事实。

## 修改纪要流程

1. 用户直接描述修改要求；从逐字稿选区选择“用这段更新纪要”时，会明确进入下一次修改意图。其他输入由本地前端根据写入/修改措辞判断，默认按问答处理。
2. 服务端根据要求与逐字稿证据选择最多四个候选 Markdown 章节。
3. LLM 只能返回一个候选章节的完整替换块。
4. UI 以“准备更新”卡展示目标章节、修改说明、修改后短预览和可展开的完整前后内容。
5. 用户选择“保存到纪要 / 继续调整 / 取消”；只有保存才会写入。
6. 写入前再次校验纪要 revision，在 `.history/minutes/` 保存旧版本，再原子替换文件。
7. 保存后可立即撤销；只有当前纪要仍是该次修改产生的 revision 时才恢复，避免覆盖后续编辑。

如果逐字稿或纪要在预览后发生变化，保存或撤销会返回冲突，要求重新生成预览或人工检查。

## 结论审计流程

结论审计用于判断纪要中的结构化结论是否被原文和画面依据支持，不调用模型，也不直接修正文档。

1. 用户选择会议并切换到“结论审计”，默认范围为“重点结论”，只包含非 informational 的决定、共识、提议、正式行动、风险与未决问题；开场、出席、议程、页面事实和普通信息记录保留在“全部证据”，不占用首轮审计队列。
2. 卡片展示结论状态、类型、发言人、逐字稿数量和页面数量；“核对依据”定位左侧原文、录音和画面。
3. 用户选择“正确、提议不是决定、应该是决定、证据不对应、负责人/期限错误、原文没有该信息、暂时无法判断”之一，可附加说明。数字键 1–7 对应七种判断。
4. 每次判断立即写入本机 `evaluations/<meeting>.json`，并更新完成率、问题数和筛选结果；正式纪要保持不变。
5. 评测事件只保存 claim ID、来源结构指纹、标签和备注，不重复保存纪要或逐字稿正文。
6. 指纹覆盖结论及其实际引用的逐字稿/页面来源。相关内容变化时原判断失效；无关段落变化不会让全部结果失效。

首轮审计的目标是发现模型和提示词的稳定失效类型。审计结果不会自动训练或改写 prompt；需要先汇总问题，再由人工确认是否调整策略并运行下一轮对比。

## 三层会议阅读

同一批源数据按阅读目的投影为三层，不重复生成三份相互冲突的事实：

1. “会议纪要”回答整场会议最终讲了什么，以说话人身份、逐字稿、VL 页面和 evidence claim 的整合结果为主，只呈现常规纪要；canonical 文件中为证据/RAG 保留的逐页详情不再重复铺在阅读页底部；
2. “会议脉络”回答整场会议围绕哪些核心论点展开。它以整场会议为根，归并出 3–8 个一级论点；首屏只展示根与一级论点，选中后才展开该分支的背景、观点、约束、决定、行动、风险和待确认等类型化子节点。相同论点在不连续时间再次出现时仍是同一分支。点击分支只建立语义聚焦，时间范围提供显式播放入口。截图、页面变化、时间窗和说话人都只能作为依据，不能直接成为节点；
3. “屏幕内容”回答屏幕上具体展示了什么。左侧以缩略图、标题、时间、信息价值和讨论状态组成资料列表；右侧查看一份完整 VL 解读及全部出现区间。低信息画面默认折叠但不删除；页面只展示而没有被口头讨论时，不能据此推断会议作出决定。当前屏幕可打开沉浸式预览，在 125%–300% 间缩放、双击放大并前后切换逻辑页；切页更新播放时间与共享 Focus，但不自动播放，关闭后回到原阅读位置。

产品内部区分三个概念：`Segment` 是页面或摄像头画面的一次连续出现，`Chapter` 是兼容旧会议的连续讨论时间段，`Topic` 是可跨时间复用的语义主题。右侧脉络和时间线上层以版本化的 `meeting-topic-map/v1` 为准；旧 Chapter 只在 Topic Map 尚未生成且纪要本身有少量明确议题时用于时间导航，不再把几十个视觉 Segment 伪装成章节。

Topic Map 由本机 LLM 两阶段生成：先按约十五分钟窗口提取候选论点，再从整场视角归并为 3–8 个一级论点和 2–7 个结构子节点。每个节点必须引用现存 T/P/C ID；无有效依据的节点丢弃，决定和行动状态服从 canonical evidence。sidecar 与逐字稿、纪要、页面和 VL 描述 revision 绑定，任一输入变化后旧图不再展示。同一逻辑页离开后再次出现仍生成新的 Segment，因此屏幕层可分别跳转，但只共享一份 VL 解读，不增加 Topic 数量。

## 渐进式纪要发布

带屏幕录制的会议不再等待全部 VL 才首次出现内容。语音转写和说话人完成后，工作台自动打开带明显进度条的“语音草稿”；草稿已可播放、搜索、翻译和追问，并明确告知数字、表格和画面语境仍在补充。语音草稿的文本模型请求关闭 thinking，优先保证可读正文；如果草稿仍失败，界面明确解释“草稿失败，正在生成多模态终稿”，绝不继续显示空白“暂无纪要”或误报“草稿可读”。VL 终稿完成后在同一会议中替换纪要，优先按同名标题保留阅读位置，之后再开放编辑、结论审计、Topic Map 和导出。这是两个有版本语义的阶段，不是在用户无感时悄悄改纪要。

## 离线分享

“分享 / 导出”先运行只读预检，展示 evidence 状态、有来源链接的结论数、逐字稿/页面数量、媒体可用性和压缩后预计大小。默认生成不含音视频的 `.meetingpack.zip`；顶层只有 `viewer.html`、`README.txt` 和 `assets/`。Viewer 与在线工作台保持同一阅读层级：通过质量门槛时默认打开“会议脉络”，否则回退“会议纪要”，并保留“屏幕内容”和右侧证据核对；不再让收件人在四种管理层/执行层重排视图中做二次选择。无视频时，冻结截图作为内容舞台随音频或时间选择切换；音频选项生成 AAC 40kbps 分享版，视频选项生成 720p/10fps 分享版，两者都不修改项目中的原始母版。格式与 RAG 规则见 `docs/EXPORT_AND_RAG.md`。

离线包与中心智能版是两个清晰模式：离线包必须依靠导出时预生成的阅读视图、完整逐字稿和证据跳转完成理解；中心智能版由轻量 Viewer 调用有算力机器上的 RAG/LLM。不能要求收件方运行模型，也不能把无鉴权的本机接口直接开放到网络。

MeetingPack v4 已达到上述离线基础目标。会议脉络复用导出时冻结的 Topic Map，不再次让 Viewer 调用 LLM；屏幕标题和详情在进入 Viewer、Evidence 和 RAG 前统一清理 `<think>/<analysis>`。旧纪要缺少 marker 时仍能完整阅读和播放，但会显示 `partial` 告警。导出不会修改会议目录或媒体母版。自由问答仍只属于中心智能版，不会在静态 HTML 中伪造一个不可用的聊天入口。

## 阅读体验 P0（2026-08-12 已实现）

本轮把 2026-08-11 走查的阅读连续性与状态语义落到产品中：

1. 刷新后恢复上次会议、有效 revision 下的逐字稿轮次/纪要标题、语言和分栏比例；内容变化时安全回到顶部；
2. 标题区展示资料、证据与分享状态；证据不足时质量入口改名提示，不伪装成正常验收；
3. 视频播放器提供紧凑/展开状态，逐字稿/纪要分栏可拖动并记忆；时间线拆成播放进度和章节/页面两层；
4. 底部宽助手改为右侧 AI/证据智能栏，并按有无 claim 给出确定性建议问题；
5. 作业面板使用可读会议名、中文阶段和翻译完成量，不再把原始 slug 与英文状态作为主信息；
6. 导出改为预检向导，显示证据完整性、媒体可用性和预计包大小；
7. 1024px 及以下会议库改为抽屉，390px 使用上下阅读布局和全宽智能栏。

本轮又把在线阅读调整为“会议脉络 / 常规纪要 / 屏幕内容”：常规纪要移除重复的逐页详情；整场脉络以 AI Topic Map 展示“会议根—一级论点—类型化子节点”，同一论点可绑定多个时间范围。合格脉络成为第一眼，首屏只展示一级论点，当前分支按需展开；节点选择建立跨播放器/画面、时间轴、逐字稿和结论的共享 Focus，但不改变播放时间，显式时间入口才跳转。屏幕内容列表直接显示缩略图与标题，并区分核心/参考/低信息及讨论状态。页面检测默认排除右侧 15% 参会人栏、抑制稀疏红框/激光点，并对顶部大标题单独增强：讲解标注不新建页，同表格但标题变化仍新建页。导出 Viewer 同步相同三层和 Focus 语义，无视频时用截图内容舞台补足时间上下文。助手侧仍待补 SSE 流式段落、停止和“检索→核对→组织回答”阶段提示。

同类项目调研、响应式问题、目标架构和分阶段验收标准见 `docs/UX_REVIEW_AND_REFERENCES.md`。
